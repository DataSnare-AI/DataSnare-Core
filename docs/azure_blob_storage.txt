Core Azure Blob storage setup

Core uses a distinct Fernet key from AIOps. Generate a key and store it in the
deployment secret store; do not commit or paste the key into documentation.

The SAS credential and Fernet key were exposed during troubleshooting. Revoke or
rotate the SAS through its stored access policy in Azure. If the Fernet key was
used to save credentials, re-save replacement credentials under a new key before
discarding the old key; changing it first makes existing encrypted values unreadable.

In Core Admin > Storage, use:
- Backend: Azure Blob Storage
- Container: dscoreartifacts
- Blob prefix: core-artifacts
- Account URL: https://forensicit.blob.core.windows.net
- SAS token: query-string token only, not the complete SAS URL

Set CORE_STORAGE_ENCRYPTION_KEY in Core's .env.core before saving Azure secrets.
Keep the key stable across Core restarts and rebuilds. Start Core staging separately
from AIOps with:

docker compose -p datasnare-core --env-file .env.core -f docker-compose.staging.yml up --build -d

StorageBlobLogs
| where TimeGenerated > ago(1h)
| where OperationName == "GetContainerProperties"
| extend Container = case(
    Uri contains "/dscoreartifacts", "dscoreartifacts",
    Uri contains "/dsaiopshelprepository", "dsaiopshelprepository",
    "other")
| where Container != "other"
| extend ClientIp = extract(@"^([^:]+)", 1, CallerIpAddress)
| summarize
    Requests = count(),
    Successes = countif(toint(StatusCode) < 400),
    Failures = countif(toint(StatusCode) >= 400),
    Results = make_set(strcat(StatusCode, " ", StatusText)),
    AuthTypes = make_set(AuthenticationType)
  by Container, ClientIp
| order by Container asc

Need to get past the 7 day user SAS expiration.
1. Enable VM Identity
In Azure Portal:
Open the VM hosting Core.
Select Identity → System assigned.
Set Status: On, then Save.
Note the displayed Object (principal) ID.
This is the VM’s identity, not your personal Azure account.
    on vm dsaiops01, Identity-->System assigned, turn on then save
    Object (principal) ID:  69b48efd-9ee0-4fe6-b6d6-06e1969938e4 -- this is VM identity

2. Grant Blob Access
Open the storage account containing your existing artifact container:

Prefer the specific container’s Access Control (IAM) for a narrower scope. Storage-account IAM also works but grants broader access.
Select Add → Add role assignment.
Choose Storage Blob Data Contributor.
Under members, select Managed identity.
Select your subscription, identity type Virtual machine, and the Core VM.
Select Review + assign.
Allow several minutes for permissions to propagate. You do not need Storage Blob Delegator for Core’s direct uploads.

3. Switch Core Away From SAS
In Core Admin → Storage, confirm and save:

Backend: Azure Blob
Account URL: https://YOUR_ACCOUNT.blob.core.windows.net with no SAS query string
Container: your existing container
Blob prefix: retain core-artifacts
